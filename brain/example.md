**目的**：用虚构书签任务展示解释、修改、续作、整改与停止的不同交接。

**适用于**：学习 Brain 选择组织入口或专项 Agent 的路由边界；本文件不提供真实工程运行或独立审查证据。

# 书签任务：逐轮路由示例

以下请求、工程与状态全部为独立虚构，用于说明路由判断；没有实际修改 Java、运行测试、调用模型或产生独立审查回执。既有[书签标签案例](../examples/workflow-bookmark-tags/README.md)仅作可阅读的流程参考，其运行证据不归本示例所有。

| 本轮请求或事实 | 选择与交接 | 本轮不能推断的结果 |
| --- | --- | --- |
| “解释标签替换为什么应保留未指定字段，先别修改。” | 采用[语义审查者](../agents/semantic-reviewer.md)职责，解释给定契约；无多任务依赖和重复需求，不选 Graph 或 Loop | 解释不授予改码或访问外部服务的权限 |
| “现在修复我的本地书签工程，允许改标签服务及相关测试。” | Brain 直接选择[研发 Workflow](../workflows/java-spring-development.md)，先确认实际根、基线、完整差异及验收；需求职责确认保持项后交实现、验证与审查阶段 | 工程与验收尚未给出时，只停依赖它们的实现；不能复制教材结果为本任务通过 |
| “测试已经通过，继续。”但没有候选与测试记录 | 交回原协调 Agent 复用 Workflow，由验证职责补核当前候选、命令与断言，再进入要求的审查 | 用户描述是输入；当前缺证不能标成已核通过，也不因继续重跑已知有效阶段 |
| 同候选审查发现空列表语义错误，原任务已允许有限整改 | Brain 为原任务选择[整改 Loop](../loops/review-convergence.md)，沿原协调者与 Workflow 接续，将具体发现交原作者；修订后复验相交测试和审查，沿用累计预算 | 新候选不能继承相交旧审查绿灯；没有预算则先保留发现并交接 |
| “停止，明天接着看。” | 保存当前责任、候选、已完成/未完成、在途未知和恢复点，停止相关新动作 | 不自动预约、启动后台或假定明天已获得发布授权 |

一次最小交接可以写成：

```text
目标：修复虚构书签工程的标签替换，保留未要求变化的字段。
入口：Brain 选择研发 Workflow，由该流程组织协调者与阶段 Agent；处于验证输入补齐阶段，无需多任务 Graph。
执行方式：当前助手采用验证职责，没有启动独立验证 Agent。
授权：仅本地标签服务及相关测试；提交、推送、部署未获授权。
候选与测试证据：未知，不能声明通过。
下一步：核实际工程和完整候选，取得测试命令与结果，随后进入必要审查。
```

自查本示例时，核解释未变修改、继续未重置预算、候选变化使相交证据失效、停止未转后台四个边界。此核对只属于文档自查，不能证明宿主自动执行这些约束。
