# 职责路由

目的：将当前任务交给适用的现有组织入口，保留职责、授权和恢复边界。只在目标或前提变化时重新选择；本表的顺序是适用性判断顺序，不是强制启动顺序。

## 先选组织方式

| 任务条件 | 选择入口 | 排除与交接 |
| --- | --- | --- |
| 多个任务有依赖、并发额度或汇合要求 | [Graph 目录](../graphs/README.md) | 核图定义是否覆盖任务；不能把任意自然语言直接当作可执行图。单个改动通常不需要 Graph |
| 同一目标有明确失败、待补证或审查发现，需要有限重复 | [Loop 目录](../loops/README.md) | 核累计预算及停止条件；没有具体重复理由不启动。单轮仍由相应 Workflow 承担 |
| 需求涉及实现、验证及审查等阶段交接 | [Java/Spring Workflow](../workflows/java-spring-development.md) | 输入包含需求、工程、候选与写集。需要原生派工时另核[原生 Workflow](../workflows/native-java-spring.md)前提 |
| 仅解释、单项诊断或专项审查，且无适用上层要求 | 下方专项职责 | 采用相应角色职责；不是阅读角色文件就已启动子 Agent |

已有适用流程时在原流程中选择阶段职责，不由 Brain 另组一条平行执行或审查链。缺匹配入口时明确缺口，继续独立且已获授权的部分，不自动造新能力。

## 再选阶段责任

| 当前需要 | 责任入口 | 输入与边界 |
| --- | --- | --- |
| 澄清目标、保持项与验收 | [需求负责人](../agents/requirement-analyst.md) | 用户诉求和已有事实；关键语义未定先澄清，不将建议当决定 |
| 实现已确认改动 | [实现者](../agents/implementer.md) | 当前契约、完整候选与写集；保留既有行为，提交和发布另核授权 |
| 判断未知失败原因 | [诊断者](../agents/diagnostician.md) | 合法取得的失败证据及反证；已有确定缺陷直接回原作者，不重复排查 |
| 核行为、代码、需求语义或查询风险 | [验证者](../agents/verifier.md)、[代码审查者](../agents/code-reviewer.md)、[语义审查者](../agents/semantic-reviewer.md)、[查询审查者](../agents/query-reviewer.md) | 按实际问题选择；只审给定 SQL 不表示可以执行 SQL 或 DDL |
| 核范围、目的、保留和完成声明 | [原则审查者](../agents/principle-reviewer.md) | 同候选与证据；原则判断不替代功能、语义或业务验收 |
| 核说明与实际能力一致 | [文档审查者](../agents/document-reviewer.md) | 当前成果及使用入口；自查与分离审查如实区分 |
| 整理交付顺序、残余与恢复条件 | [交付规划者](../agents/delivery-planner.md) | 当前候选、证据和许可；规划不自动执行 Git、发布或部署 |

新增外部数据采集、生产接入或本表未覆盖职责时，先核实际项目规则与当前可用能力，不从角色名推导权限。本仓库没有通用生产数据连接器。

## 续作、变化与停止

| 本轮输入 | 接续动作 |
| --- | --- |
| “继续”，目标和前提未变 | 恢复原任务状态与下一责任人，复用有效前缀，不重建流程或重置预算 |
| 补充验收或纠正语义 | 交需求职责判断受影响范围；相关实现和证据重新核验，保留无关结果 |
| 改变候选、环境或授权 | 只失效依赖这些输入的阶段；授权未包含的动作保持待处理 |
| 已受理操作超时、返回不明 | 当前责任人先查受理状态和恢复记录，不换身份重放 |
| 要求停止 | 停止相关新动作，记录在途/未知、最后可信状态与恢复条件，不预约后台继续 |
