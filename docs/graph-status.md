# Graph 交付范围与后续事项

本批实现通用固定输入目标图，并以独立虚构文件实际接通巡检/缺陷两个 Loop。它不代表所有本地 Graph、生产适配或旧协议都迁移完成。

## 已实现及如何核证

| 小步 | 已有成果 | 证据边界 |
| --- | --- | --- |
| G0 | [Loop 完成范围及五项待办](loop-status.md)、[Graph 顺序计划](graph-delivery-plan.md) | 沿真实既定交付/未迁/未验记录，不声称所有 Loop 完成 |
| G1 | 唯一目标、完整验收、DAG/写集、只读 Gate 与显式 closure 准入 | 定义反例测试；无任意 shell 或旧协议转换 |
| G2 | 有限并发、失败分支隔离、原子持久化、锁与安全前缀接续 | 实际线程、私有文件和跨进程检查点；UNKNOWN 不重放，非系统沙箱 |
| G3 | 候选/原范围/操作义务、实际文件与注册程序的 Gate 快照、最终 closure | 确定性程序校验及负例；不是模型或外部独立审查 |
| G4 | [双目标图](../graphs/examples/goal-loops/README.md)真实调用现有 Loop，前台命令/暂停接续 | actual Graph/Loop programs + 虚构日志/接口/构建/业务及模拟审查；无真实模型/服务/部署 |

运行 `python3 -B scripts/check_all.py` 和 `python3 -B scripts/check_ci.py` 验仓库与全部便携回归。每步按计划在本地验证后单独提交、推送，并核对应 SHA 的五个 CI 任务；最后版本的远程结果以实际 Actions 回执为准。CI 的真实 Spring/MockMvc 仍只覆盖公开冻结候选，不能替代新目标图的业务验收。

## 仍保留的边界

| ID | 尚未覆盖 |
| --- | --- |
| GRAPH-01 | 文档治理、目的治理专用图，待相应 Loop/Workflow 适配后单独迁移；不靠通用引擎冒充已接通 |
| GRAPH-02 | 新目标图到真实模型、外部巡检、制品/业务执行平台的适配；现有原生/构建/Docker Graph 保留自己的旧验证范围 |
| GRAPH-03 | 运行中变更目标/候选后的动态重规划、跨协议/跨版本自动恢复；当前固定输入身份变化拒绝接续，未知动作必须先查原状态 |
| GRAPH-04 | 跨宿主统一资源/业务写权、恶意多租户隔离及任意回调强杀；实际适配器负责内层超时和既有执行隔离，不据线程等待超时声称子进程已停止 |

组织专属业务参数、真实记录和私有知识来源没有纳入本批公开内容；本计划不启动任何后台、业务发布或生产动作。Loop 未完成事项继续从原 [LOOP-01 至 LOOP-05](loop-status.md)接续，不因 Graph 已接入两类 Loop 而关闭。
