## Workflow阶段与职责

- 需求：需求负责人确认对象、作用域、保持项与验收，输出已决/未决及可实施范围。
- 设计/实现：实现者选择现有Skill，核基线与旧行为，交候选、差异、验证计划和真实自查。
- 验证：验证者核装配、接口行为、拒绝和必要保持项，区分静态、MockMvc、外部集成与未运行。
- 冻结审查：固定候选完整身份、需求、差异及执行证据；代码审查、语义审查和原则审查只消费同一候选并给各自结论。
- 整改复验：原作者处理具名发现，验证者和相应审查职责复核失效项；无新变化保留有效前缀。
- 交付：规划者核任务验收、证据、依赖、未决及下一负责者，不自批上线；文档审验按文档改动条件接入。

诊断、SQL、文档审验按真实触发选择既有Agent，不要求为了形式执行所有角色。关键缺证只停相交目标，不凭其他阶段通过洗成全目标完成。Workflow是可由宿主消费的合同，不是自动调度器或新增权限来源。
