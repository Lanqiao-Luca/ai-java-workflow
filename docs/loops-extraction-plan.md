# Loops 公开抽象执行文档

目的：为 Java/Spring 研发提供有界重试、整改收敛与停止交接的方法，保留当前公开 Workflow 的职责和验收边界。

## 范围与公开条件

独立编写正文、空表和虚构控制情景。不复制私有实现、历史参数、业务样本、运行记录或平台路径。原材料只读，来源映射及排除记录存于公开仓库之外。无法确认的内容不进入候选。

Loop 决定同一目标下是否重复、等待或停止；Graph 管目标与依赖，Workflow 组织单轮阶段，Agent 经 Skill 消费方法。没有重复需要时直接使用现有 Workflow。技术重试次数与整改轮数分别记账，共享上层有限时间预算。

## 按业务目的分步交付

| 步骤 | 产物 | 验证后交付 |
| --- | --- | --- |
| 1 | 本执行文档及目录入口 | 全量清单、引用、隐私复查后单独提交推送 |
| 2 | 技术重试方法、空表、只读控制情景与离线判定参考 | 验证首轮计数、拒权、未知副作用、到限停止后提交推送 |
| 3 | 审查整改方法、空表、完整虚构接续案例 | 验证候选漂移、证据关闭、无进展停止、预算不清零及全量检查后提交推送 |

每步先完成并复查实际字节，再由项目指定提交职责白名单暂存、提交、推送和核验远程；有问题修复相交内容，未完成检查的内容继续排除。

## 接入与验收

接入现有[研发 Workflow](../workflows/java-spring-development.md)和[原生 Workflow](../workflows/native-java-spring.md)的失败交接点，明确运行身份、授权范围、候选、已消费动作、累计次数、时间及下一失效阶段。公开清单必须覆盖所有新文件，Markdown 引用必须指向仓库内实际文件。

离线判定参考只消费显式模拟事实，不启动 Agent、构建、联网、Git 写入或业务调用。它可验证控制边界，不能证明真实外部操作幂等或模型整改有效。现有原生调度器遇失败仍停止；本批次不增加其自动恢复或后台循环，也不重新宣称历史 Spring/Docker 验收。

残余发现、缺证、未知结果、最后可信阶段及恢复条件必须保留；局部完成不能代表整条研发交付完成。恢复不得重置预算、变更验收分母或重放已受理操作。
