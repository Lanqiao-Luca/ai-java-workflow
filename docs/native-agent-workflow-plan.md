# 原生Agent研发链执行计划

目标：让已公开的研发方法驱动真实、分离上下文的原生Agent调用，逐阶段产生文件、运行验证、冻结审查并交付。保留原命令型Graph及其历史证据，不把它们改称模型派工。

## 小步交付

每步先实现、验证、审查允许写集，再由提交专员单独commit、push并读回远程ref；前一步交付完成再开始下一步。

| 步骤 | 独立目的 | 验收 |
| --- | --- | --- |
| 1 | 明确原生调用合同与本计划 | 当前宿主实际加载提交专员；计划及引用检查通过 |
| 2 | 实现Codex原生派工适配器 | 真实spawn与独立Agent完成事件；异常、超时、伪完成和缺角色拒绝；离线协议测试 |
| 3 | 接通需求→实现→验证→审查→交付 | 顺序门禁、同候选身份、有限整改、失败阻断；每阶段消费公开角色/Skill/Standards |
| 4 | 独立虚构Java/Spring完整案例 | 原生Agent实际生成需求/实现/测试，真实Spring测试，分离审查，交付证据；不连接真实业务服务 |
| 5 | 入口与真实结果 | 公开清单/引用检查、使用说明、已验/未验和远程核验一致 |

第2步完成前不宣称全流程可用；第4步实跑前不宣称Spring原生研发链验收通过。每次公开只包含该步已验证成果，不批量积压所有步骤后一次上传。

## 接入与边界

- 采用本机已登录的Codex CLI；由真实原生子Agent承担任务，父调度器只交接与核验。结构化结果不代替真实工具事件与最终字节核对。缺角色/缺登录/版本不兼容明确失败，无模拟成功或默默改用其他Agent。
- 角色合同来自[现有角色](../agents/README.md)，按[完整研发Workflow](../workflows/java-spring-development.md)组织。平台注册文件只在显式运行实例中生成，不改使用者全局配置。
- 工作目录与状态按实例隔离。模型服务联网是显式前提；这与旧Docker的离线构建边界分开，不能把模型进程宣称成无网络容器。仅在可信、独立虚构的演示工程中实跑，不能擅自把任意公司工程送给模型。
- 每阶段限定输入、输出和写集；验证与审查绑定实际候选，失败阻断下游。有限整改重新执行受影响验证与审查，未知副作用先查状态，不自动重放提交/推送。
- 构建使用公开依赖与模拟配置，禁止继承公司数据库、私服、凭证和业务数据。日志、认证状态、工具缓存与私有运行目录不上传。仅发布经逐项审查的最小结果与文件身份。
- 真实仓库的暂存、commit、获授权push与远程核验必须实际委派`github_committer`；无法加载时暂停Git写操作。该项目路由属于本机运行约定，不把私有配置复制进公开仓库。
- 普通运行默认不执行远程发布。交付阶段输出可审核结果；GitHub写入必须另有本次目标、允许写集与明确授权，由指定角色单一执行。

## 验证方法

协议/门禁使用独立构造输入测试；它们不能算模型运行证据。真实案例另记录原生派工事件、候选身份、工具退出和JUnit结果。原始会话保留本地仓库外，公开回执只保留去敏的事件类型、计数、版本与摘要。

本计划只使用当前公开仓库与独立编写材料；不读取或改写私有原框架，不上传公司信息。每次修改后复查实际待公开文件，来源或内容有疑问的文件先排除。
