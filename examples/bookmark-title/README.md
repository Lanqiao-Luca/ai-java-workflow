# 完整链路：实现者处理书签标题规范化

目的：让使用者看见一个 Agent 如何接任务、消费 Skill、落实规范并交回可审候选。全部代码、对象和规则独立虚构，不来自真实系统。

此案例具备完整输入、变更前后源码、差异、验收用例和填写后的交接。它演示 **纯 Java 服务层**，可作为 Spring 项目中的独立业务单元；没有 Spring 注解、容器、数据库、HTTP 或模型调用。Java 当前实跑状态以[结果记录](result.md)为准。

## 需求已决定什么

允许书签所有者修改标题，新标题按 Java `String.trim()` 处理首尾空白，结果为空时拒绝。保留所有者权限、版本冲突拒绝、标签、收藏序号，以及成功变更后的版本递增和审计。规范化后标题不变时不写入、不增版本、不增审计。

空白处理只承诺 `trim()` 的范围，不额外承诺完整 Unicode 空白规范化。调用身份由上游可信边界提供，这不是身份认证实现。内存锁只说明本进程的检查/写入原子区，不代表数据库或分布式并发正确。

## 怎样采用 Agent

在支持读取本地文档的 AI 工具中，从项目根手动给出下列请求：

> 按 agents/implementer.md 承担实现者职责。先读取 skills/code-implementation/example.md 和 examples/bookmark-title/task.json，核变更前源码，再通过代码实现 Skill 消费相关 Standards。解释现有行为与最小改点，对照已给候选及用例交自查和待验项。当前只审阅此虚构案例；不修改全局配置，不连接服务，不提交或发布。

这是可复制的任务示例，不保证任何平台自动发现、派发或强制执行。案例记录由当前作者手动采用这些职责完成，不是独立业务 Agent 的运行回执。

## 本地运行

需要 Python 3.9+ 和本地可用的 JDK 17+。从项目根运行：

```sh
python3 examples/bookmark-title/run.py
```

运行器分别在系统临时目录编译变更前后源码，使用同一套测试：前者必须暴露4个指定差距，后者必须满足12项检查。运行前先核源码身份，并核精确退出码、完整且不重复的用例集合及汇总行；只有这些断言和真实返回都符合才退出0；缺 JDK 退出2并打印NOT_RUN。它不下载依赖、不修改工程配置，也不把任意非零退出当成预期失败。
