# 已填写的职责与方法消费记录

## 接收输入与选Skill

目标：核契约到代码是否完整兑现，识别额外行为和边界反例。输入：确认契约、冻结实现、实际入口和可用测试。本案例具体文件由case.json固定；输入为作者独立构造，不是外部业务批准或历史运行证据。

选用本角色既有Skill；该Skill的“方法来源”指向现有Standards，不在Agent复制另一套方法，也不让规范反向启动角色。

## 实际判断与输出

1. 先把契约拆成必要条款，分开业务期望与代码事实。
2. 从每项契约追实现，从实现反查依据，再用边界输入找反例。
3. 核状态、单位、空值、错误与副作用语义；同名变量不代等价。
4. 输出符合、违反或缺证及受影响范围；未知业务决定回需求方。

本例将这些步骤落实为具体产物：counterexamples.json, semantic-report.md。验收逐项以case.json的evidence定位，不以目的句、文件数量、退出码或角色名称替代语义判断。

## 反例、覆盖与停止

没有可核契约时不签语义完成；只读不代作者修复，不把静态推导写为实测。只对给定输入作作者审阅/推导；没有运行Java、连接外部数据库或取得平台调用回执。若输入/候选变化，先核相交身份与旧结论有效性；本角色不重置权限、预算或既有副作用。
