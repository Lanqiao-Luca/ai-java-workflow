**目的**：固定虚构阅读清单批量归档的可观察需求与保留行为，供新设计到实现案例验收。

**适用于**：本案例单 JVM、内存状态、可解析 JSON 的虚构所有者接口；不包含真实认证、数据库、集群或部署。

# 阅读清单归档需求

- R1：`reading` 清单初始版本 1，所有者 `demo-owner`；项目 a、b 未归档，c 已归档。GET 返回版本、项目ID/标题/归档状态，顺序和标题保持。
- R2：所有者 POST `/lists/reading/archive`，请求带非空 ids 与 version；先确认清单和所有者，再进行业务输入和版本判断。`X-Actor` 仅模拟身份，不是安全认证；框架 JSON 解析在业务判断之前。
- R3：ids 中 null、空白或不存在ID使整个请求失败；所有字段/项目与版本验证通过之前不改任何状态。重复ID只处理一次，不修改调用方集合。
- R4：版本不符返回409，包括当前请求本会是 no-op 的情况。有效改变将所有目标归档且清单版本仅加1；全已归档则 no-op，版本不变。null version/ids、空列表返回400，未知项目404，非所有者403。
- R5：同一实例对相同旧版本的两个有改变请求并发，至多一个成功提交，另一个409；校验与提交处于同一锁内。单次失败保持版本、所有归档状态及标题/顺序。

只执行本机 MockMvc/服务测试，不启动对外 HTTP 端口、不调用外部业务服务。不以测试 Header 代真实认证方案。
