# 已填写的职责与方法消费记录

## 接收输入与选Skill

目标：把实现、验证、审查和发布分开，组织有依赖及恢复条件的真实计划。输入：当前候选身份、逐项证据、依赖、许可与未完成目标。本案例具体文件由case.json固定；输入为作者独立构造，不是外部业务批准或历史运行证据。

选用本角色既有Skill；该Skill的“方法来源”指向现有Standards，不在Agent复制另一套方法，也不让规范反向启动角色。

## 实际判断与输出

1. 逐项核当前候选的状态和证据，旧版本结果不能直接复用。
2. 按依赖列可继续和等待部分，给每个缺项责任与恢复条件。
3. 分开计划批准、动作受理、执行结果和现场验收，不把部署成功等同业务成功。
4. 输出最小接续计划，不代执行者发布或重置预算。

本例将这些步骤落实为具体产物：status.md, plan.md。验收逐项以case.json的evidence定位，不以目的句、文件数量、退出码或角色名称替代语义判断。

## 反例、覆盖与停止

必要证据缺失不得标就绪；没有部署许可只交计划，不补默认授权或后台流程。只对给定输入作作者审阅/推导；没有运行Java、连接外部数据库或取得平台调用回执。若输入/候选变化，先核相交身份与旧结论有效性；本角色不重置权限、预算或既有副作用。
