**目的**：在同一获准操作中恢复瞬时故障，保留受理状态、未知与总预算。

**适用于**：已有安全重放依据的瞬时失败；拒权、输入错误和业务失败不原样重试。

# 技术失败的有界重试

## 适用条件

已选定一次 Workflow 操作，失败原因可能短暂消失，且有可核实的安全重放依据。权限拒绝、输入合同错误、业务校验失败及验收未通过需要处理原因，不原样重试。

## 输入

使用[重试空表](templates/technical-retry.md)记录稳定 operation_id、当前输入/候选身份、授权与操作类别、真实回执、有限总尝试数和查询数、累计用时、绝对截止。总尝试数含首轮；查询只查原操作，不夹带写入。示例额度由案例自行选择，不是全局默认。

## 操作步骤

1. 核身份、范围、时间和已受理结果。换窗口、换候选或换工具不能清零账本。
2. 发起前先占用并保存一次 attempt；即使返回未知，也已消耗。首轮成功直接交回 Workflow。
3. 未知结果只能在授权、原句柄及有限查询额度齐备时查原结果；没有条件则交接未知，禁止重新发动作。
4. 确认瞬时失败且可安全重放后，检查剩余次数、累计时间及截止，再决定下一次。等待/退避也计时，下一次等待会越截止时停止。
5. 认证/权限拒绝、确定不可重试、无新条件、次数或时间耗尽即停止，保留原因和最早恢复点。不要换工具绕过拒绝。

## 输出与角色职责

本方法要求调用方记录 DONE、ATTEMPT、QUERY、HOLD 或 STOP，以及对应理由；这些控制含义不覆盖宿主原状态。离线参考函数仅返回状态字符串，理由及真实账本由调用方保存。调用方执行决定，Workflow 交给相应 Agent 处理一次操作和回执；Loop 不直调工具，也不授予提交、部署或其他写入权限。

接入[研发 Workflow](../workflows/java-spring-development.md)的失败归因与复验交接；[原生 Workflow](../workflows/native-java-spring.md)的未知技术结果仍停止。已确认的测试或审查失败另走[恢复控制器](../docs/native-recovery.md)的整改路径，不把业务整改计作瞬时技术重试。本方法本身不安装自动技术重试钩子。

## 验收方法

运行 `python3 -B scripts/check_loop_cases.py` 检查纯离线参考：首轮计数、瞬时失败恢复、未知查询、拒权和预算边界。参考函数只接收调用方提供的事实，不验证真实外部幂等，也不持久化账本或执行调用。

## 异常与停止

身份漂移、账本缺失、计数不可信或未知副作用保持 HOLD/STOP。恢复先对齐原回执与身份，保留旧尝试和用时；有明确新预算时保留调整来源与旧消耗，不能伪造原额度。结果的范围仅限当前操作，不能据一次成功宣告整个 Graph 完成。
