**目的**：将确认的文档修改写入正确位置，核目的、适用、原件保全和实际读回。

**适用于**：已确认项目与精确写集内的本地 Markdown 创建、更新和维护；不代业务事实判定或外发。

# 文档维护

## 输入与标准消费

接收责任 Agent 给出的目标、读者、来源/候选、实际工作根、允许写集和验收。先消费[目的与适用对象](../../standards/document-purpose.md)，返回目的相符/拟变化/未知与适用匹配/不匹配/待核及依据。

新建或修改方法原子时同时消费[原子属性](../../standards/atom-properties.md)，导航和模板不伪装成原子。按需要采用[按需加载](../../standards/progressive-loading.md)、[原件保留](../../standards/document-retention.md)；方案或执行文件再消费[上下文拆解](../../standards/context-budget.md)和[执行接续](../../standards/execution-records.md)。规则正文保持单源，已有有效判断直接复用。

## 写入与检查

1. 核当前目的、正文和实际差异，将新声明从真实职责归纳；变更职责的必要决定沿当前授权，不用补字段扩大承诺。
2. 核精确路径、原候选与已有修改，必要时在授权位置保全原字节和版本；历史原件不注入新头部。
3. 完成当前写集，读回实际字节，检查正文、来源、引用、模板语法与目的/范围是否一致。
4. 使用[文档声明检查工具](../../tools/document_contracts.py)核字段位置、清单和历史字节；如需修改公开清单与档案旁证，同步到相应入口。结构通过不代语义判断。
5. 将候选身份、前后差异、目的和适用判断、实际检查、缺项与恢复条件交回责任 Agent。需要分离审查时由上层安排，本 Skill 不自行启动角色或发布。

## 异常与停止

并发冲突或结果未知先读回，不盲重写；目的不明、来源不清或关键前置缺失只停相交动作。没有跨设备恢复、强锁或身份认证实现时不作这些保证。
