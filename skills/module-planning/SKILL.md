**目的**：将设计边界适配成单一机器模块计划与可读交接。

**适用于**：设计/有效需求、仓库基线和规划范围已明确的模块拆解。

# 模块实施规划

## 输入与方法来源

接收责任 Agent 给出的当前目标、来源/候选、读写集、预算、验收及恢复点。方法单源：

- [design-inputs](../../standards/design-inputs.md)
- [module-planning](../../standards/module-planning.md)

## 适配步骤

1. 消费输入与模块原子，核有效需求、设计身份、实际仓库/基线和不可拆边界；未获实施许可仍可生成标明用途的准备规划。
2. 从[结构模板](templates/plan.json)实例化模块；逐项分配主责、写集和验收，共享文件留唯一写者，消费者只经依赖使用。
3. 经[规划检查工具](../../tools/module_plan.py)比较独立交入的设计合同与模块计划，检查覆盖、候选身份、基线声明、一致性边界、写冲突及依赖环。设计合同必须由责任人核来源，不能从被审计划反推并自证。
4. 工具返回 STRUCTURE_VALID 只说明声明结构一致；角色另核事实、设计成熟度与当前许可，输出准备/阻塞/可交接的实际结论。
5. 设计或基线变化局部刷新并保旧修订；人读说明从同一 JSON 生成或核对，不维护第二份权威计划。

## 输出与边界

返回当前候选、方法覆盖、来源/假设、实际检查与未验、阻塞及下一责任。文档保存沿现有文档维护职责；Skill 不自行选择或启动上层流程。角色负责结论、授权和交接，工具不签语义或业务通过。
