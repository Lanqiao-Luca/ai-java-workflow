**目的**：保存执行定义、唯一状态、必要事件和产出引用，使任务能从真实断点接续。

**适用于**：供当前方法的责任 Agent、作者与审查者使用；当前任务需要可恢复的 Workflow、Loop、Graph 实例或明确的 Agent 交接时。不为简单问答另造运行包。

# 执行记录与跨窗口接续

## 适用条件

当前任务需要可恢复的 Workflow、Loop、Graph 实例或明确的 Agent 交接时。不为简单问答另造运行包。

## 输入

目标与授权、候选、选中合同和模板身份、实际责任人、当前阶段、预算及已有记录。

## 操作步骤

控制动作开始前保存计划定义和初始状态；保目标、边界、阶段/节点输入输出、验收、预算和失败恢复点。模板不是本次计划。定义变更保新旧版本，说明相交证据失效，不倒填事前记录。

每个任务只有一个总体状态写入者；最高实际启用层保总体进度，子层返回局部结果。使用稳定定义、当前状态、必要事件和产出引用四个逻辑组件，现有单份状态足够时不机械创建四份文件。

在可恢复步骤、结果、失败、决定或暂停后记录实际时间、责任、候选、动作/受理标识、结果、证据与下一步。未知副作用先查受理状态，未确认完成不重放。每项产物绑定来源、版本或 SHA、验收方式、未验及下一消费者。

接手时核工程、当前授权、原计划/候选、当前写入者和在途未知；正式交接后再写。保留完成前缀与累计预算，从首个就绪未完步骤继续。多文件保存、写前核 SHA 和读回不是并发事务或全局锁。

## 输出

唯一实例位置、真实状态、产出定位、未决、下一责任及安全恢复点。

## 角色职责

责任 Agent 记录与交接；Workflow 组织阶段，Loop 管累计轮次与预算，Graph 管依赖。持久化由相邻 Skill 适配，不由 Brain 跳层执行。

## 验收方法

另一获准执行者能按记录定位已完成、未完成和未知动作；只读定位、真正接管、继续执行及业务验收分别说明。

## 异常与停止

冲突、源不可用、身份不符或授权缺失只冻结依赖动作；旧运行保持原字节与历史，不补造旧版本已经遵循新计划格式或先后顺序。
