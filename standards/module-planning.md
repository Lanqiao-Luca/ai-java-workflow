**目的**：按需求归属、写集和一致性边界拆出可交接模块，避免遗漏与冲突并行。

**适用于**：技术方案作者、专业复核者或模块规划者，经各自 Skill 在明确目标、候选、来源和授权范围内采用；具体前提按正文。

# 设计到模块的实施规划

## 适用条件

已有当前设计身份、有效需求及工程边界，需要形成实施包。草案可以做准备规划，但不能因此宣称设计已通过或可以实施。

## 输入

设计/需求身份、有效项及各自验收、实际仓库与基线、事务/契约/方法等不能拆散的边界、允许写集、已有模块计划和变更原因。

## 操作步骤

1. 核当前来源和阶段决定，区分有效项、被替代内容、历史证据、待决和矛盾；只有当前有效项进入实施覆盖，待决必须保留影响及恢复条件，不能静默漏掉。
2. 按可验证结果、仓库写集和一致性边界拆模块。每个有效需求只有一个主责模块；每模块只写一个实际仓库。模块数量由真实边界决定，不继承私人来源的固定数量。
3. 为每模块列需求、基线、精确文件写集、验收、依赖和阻塞。事务或同方法的不可分改动归同一主责；共享文件只有一个写者，其消费者取得依赖产物，不并行改同一文件。
4. 核文件及父子路径冲突、依赖有效性和无环；区分开发依赖、合流顺序与整体集成验收，不能将局部完成改写成全目标完成。
5. 刷新时只改受设计变化、基线漂移或审查发现影响的模块，保旧计划身份与修订理由，受影响输入需重新核验；准备包与就绪包分别标明。

## 输出

单一机器规划源、需求主责映射、模块输入输出与依赖、共享写者、实际风险/阻塞、验收及接续；人读说明必须从同一规划导出，不维护两个互相漂移的权威源。

## 角色职责

模块规划者经 Skill 适配合同与工具，协调 Agent 决定后续组织；实现者只接受已核当前基线和获准写集。规划不自行启动 Graph、改工程或发布。

## 验收方法

有效需求全部归属且无重复主责，边界未拆散，写集不冲突、依赖闭合且无环；结构工具通过只说明声明内部一致，不能确认需求正确、基线真实或已获实施权限。

## 异常与停止

来源冲突、孤立需求、基线漂移或不可消解写冲突时，保待核/阻塞与具体责任，继续独立规划。预算不清零，旧计划不倒填新身份或运行事实。
