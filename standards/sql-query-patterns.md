**目的**：将连接、批量读取、索引、分页、结构与分片问题转为可复核的具体判断和验证条件。

**适用于**：查询审查者经 SQL 审查 Skill 使用；方案或代码涉及以下访问模式时逐项采用，缺证限制相交结论。

# 查询访问模式审查

## 适用条件

方案或代码涉及连接可达性、循环读取、过滤表达式、联合索引、分页、排序、唯一性约束或分片时选择对应条目。未涉及的条目标未覆盖，不强行提出改动；缺真实环境证据仍可进行限定的静态审阅。

## 输入

绑定候选及输入种类。方案提供结果语义、访问规模假设、拟议结构与排序契约；代码提供实际 SQL、动态分支/参数绑定、调用路径、权限谓词和事务边界。另核连接拓扑、数据库版本、现行 DDL/索引、分布与授权验证环境。假设、拟议结构和真实部署分别列出。

## 操作步骤

### 1. SQL 连接可达性

操作：先画出调用使用的连接与物理实例，再核 schema/table 解析和访问权限。同一 MySQL 实例的不同 schema 可以使用 `db.table` 限定名；前缀不同不能证明跨物理实例。确属不同实例时核实际连接能力及已有联邦、代理或应用聚合机制，不能凭命名推断可 JOIN 或不可 JOIN。

验收：结论绑定真实连接拓扑、限定名和权限证据。无拓扑时输出待证连接条件，不要求无依据拆查询；可达性与事务一致性分别核对。

### 2. N+1 与批量聚合

操作：标出父项读取和循环内子项读取次数，设计父 ID 集合批量读取并按键回填。保持父项授权范围、子项权限、零子项、缺失值、重复行、NULL、聚合粒度与输出顺序；空 ID 集合不生成非法 SQL，较大集合按参数限制和事务快照要求分批。父项分页先于补子项；一对多 JOIN 后 LIMIT 需验证父项数量。若建议使用冗余字段，先取得写入/补偿、回填和一致性验证证据。

验收：同一虚构夹具逐父项比较聚合及缺失语义，并记录两条路径真实查询次数、批次数和未覆盖分支。减少调用不能直接证明更快；冗余字段缺一致性依据只作为待证提案。

### 3. 表达式、函数与索引

操作：检查过滤表达式是否作用于索引列及其实际访问路径；日期过滤拟改写成半开区间时，先固定时间类型、存储格式、时区、精度、边界及 NULL 语义。核实际版本、DDL 和执行计划中的函数索引/生成列例外，不把所有函数判为必然全扫描。SQLite 文本日期的结果不外推 MySQL 时间类型。

验收：有边界样本证明等价前提，另有实际 DDL/计划才判断索引是否使用。未知时区或隐式类型转换保留待证，不机械改写。

### 4. 多列过滤与联合索引

操作：从真实谓词组合、选择性、数据倾斜、等值/范围/IN、排序和返回列提出候选列序。IN 的访问与排序效果依值数量、版本和计划判断；考虑已有索引、写入成本和覆盖收益，比较计划与目标负载。

验收：给出每个候选的适用分支、代价假设与验证条件，不机械限定索引列数，不承诺联合索引必然消除排序；缺分布或计划保留提案。

### 5. 完整排序元组与 keyset

操作：固定唯一且完整的 ORDER BY 元组（例如时间和唯一 ID），按每列方向构造字典序续页谓词，并保持 NULL、排序规则、参数精度和游标编码一致。混合 ASC/DESC 逐列展开比较；评估更新/插入、快照与游标失效。offset 是否适用取决于跳页需求、规模与测量，不一律替换。

验收：并列排序键、边界及多页样本中无意外遗漏/重复；记录并发和可跳页范围。没有一致快照不保证跨页永远不重不漏。

### 6. 过滤与排序路径

操作：分别评估先按索引过滤再排序、按排序索引扫描再过滤及小集合内存排序；结合过滤后规模、LIMIT、回表、排序内存/溢出和计划比较。排序节点本身不是严重缺陷。

验收：严重性依据结果语义、真实工作量、预算与实测影响；小集合排序可以接受。只见 EXPLAIN 的 sort 而无规模/成本时，记录风险和补证条件。

### 7. 拟议结构与已部署约束

操作：将设计中的 `PROPOSED_SCHEMA`、迁移文件、目标环境现行 DDL 分开记录；唯一性要求明确列、NULL、排序规则及适用范围。查询代码按唯一行消费时核数据库约束和存量重复，不能把文档索引名或拟议迁移当作已部署证据。

验收：分别交拟议约束、已观察约束和未证差异；内存安装唯一索引后的拒重结果只证明夹具。缺目标 DDL 时保留唯一性待证；部署与数据修复交有权负责人。

### 8. 分片路由与分片内索引

操作：核真实分片键、路由规则、谓词可路由性和扇出数量；再分析各分片内部索引与过滤/排序。全局分页、聚合和去重要核跨分片归并语义与通信成本。

验收：分别报告路由范围/扇出证据与分片内访问路径；分片内有索引不能证明没有广播，带某字段也不能证明路由成功。缺路由日志或规则只给待证条件。

## 输出

每个命中项输出：候选、输入种类、具体 SQL/分支、结果契约、发现、证据级别、反例和下一验证条件。缺证、静态建议、隔离语义实测、目标环境计划/性能测量分层；未运行不填成功。实测同时给环境、版本、样本范围和失败/未覆盖。

## 角色职责

查询审查者解释语义和覆盖；实现者处理候选修改；有权数据负责人决定结构与部署。本文不启动连接、DDL 或外部审查。

## 验收方法

逐命中项核操作与对应判据，明确方案假设和代码事实；可复现反例不含业务来源。没有目标环境证据不签生产性能或部署完成。

## 异常与停止

缺连接、DDL、版本、时区、权限或路由证据时仅暂停相交判断；继续可做的静态审阅。失败保留真实结果与最小恢复条件，不连接未知服务或执行外部 DDL。
