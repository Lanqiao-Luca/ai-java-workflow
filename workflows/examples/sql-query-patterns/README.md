**目的**：用四条可复现的内存 SQL 实验展示批量读取、父项分页、日期边界和拟议约束的证据边界。

**适用于**：查询审查者及学习查询审查的使用者；仅依赖 Python 标准库和 SQLite，样本独立虚构，不作为生产数据库验收。

# 查询访问模式案例

[查询审查者](../../../agents/query-reviewer.md)经原有 SQL 审查 Skill 消费访问模式方法。本例是局部语义实验，方案、代码和部署判断仍沿该角色交接。

执行[本地程序](run.py)：

```sh
python3 -B workflows/examples/sql-query-patterns/run.py
```

`run_examples()` 返回可 JSON 序列化的实际结果、SQLite 版本、计数与覆盖边界；命令只向标准输出写 JSON。无命令行参数或外部 SQL 入口，所有连接固定为 `:memory:`，造表、插入和建索引只影响内存夹具。程序用显式检查抛出异常，Python 优化模式不会关闭判据。

| 实验 | 输入与操作 | 验收判据 |
| --- | --- | --- |
| N+1 与批量聚合 | 三父项、三子项，逐父项聚合与批量分组回填比较 | 结果均为 `[[1,2,10],[2,1,7],[3,0,0]]`，保留零子项；SELECT 次数分别为 4 和 2 |
| 父项分页后补子项 | 父项先 LIMIT 2，再查其子项；对照一对多 JOIN 后 LIMIT 2 | 前者保留父项 1、2 和它们全部三子项，后者仅出现父项 1；SELECT 次数分别为 2 和 1 |
| 日期半开区间 | 六条事件，包括前日尾、当日起点、当日尾、次日起点及 NULL | UTC 日期函数和半开区间均返回 2、3、4，实际 SELECT 两次 |
| 拟议唯一约束 | 两个独立内存库分别仅有普通表、实际安装唯一索引 | 前者允许同值两行且索引列表为空；后者索引元数据证明已安装，第二条同值插入抛出完整性异常，保留一行；SELECT 两次，元数据读取两次 |

查询次数计数只覆盖程序执行的 SELECT，不含夹具 DDL/DML；唯一性元数据读取另列。父项分页的两条路径结果不同，单看查询次数不能评判正确性或性能。

日期等价的夹具前提为：UTC 日历日、固定宽度 `YYYY-MM-DDTHH:MM:SSZ` 文本、秒精度、默认 BINARY 文本比较；两谓词均排除 NULL。不同偏移、精度、存储类型、时区或隐式转换需要重新验证。此例没有 MySQL 计划，不能证明改写后的索引使用或性能改善。

本例只验证这些固定样本的语义与查询次数，不覆盖动态授权分支、参数上限、分片、并发一致性或真实环境唯一约束。批量例无权限模型，不据此声称授权语义已验。唯一索引夹具使用非空文本，不证明其他数据库的 NULL/排序规则语义。
